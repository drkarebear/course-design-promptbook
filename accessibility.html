Accessibility

Designed for access, not just appearance.

Course Design Promptbook is built with accessibility as part of the design process. The goal is to support WCAG 2.2 Level AA practices while keeping a dense course-design process readable and manageable.

Built into the site

What you should be able to expect

  • Keyboard-accessible navigation and controls
  • Visible keyboard focus
  • Logical headings and landmarks
  • Text that reflows for smaller screens and zoom
  • Strong text and interface contrast
  • Meaning that does not depend on color alone

Current accessibility features

Accessibility is part of the shared site structure.

Structure and navigation

Pages use semantic headings, main content landmarks, labeled navigation, breadcrumbs, descriptive links, and a skip link that lets keyboard users move directly to the main content.

Keyboard use

Links and buttons are keyboard reachable. Focus is shown with a high-visibility two-part focus indicator rather than relying on a subtle browser default.

Color and visuals

Color is paired with words, labels, numbers, or structure. Decorative icons and illustrations are hidden from assistive technology when they do not add information.

Readable interaction

Prompt text uses a constrained reading width, copy controls have specific accessible names, and copy confirmation is announced through a status message.

Reflow and motion

Layouts adapt to narrower screens rather than requiring a desktop-sized canvas. The shared stylesheet also respects reduced-motion preferences where motion behavior is present.

Brain-friendly design

Long design work is broken into small decisions, repeated page patterns, short sections, visible next steps, and quality checks so accessibility includes cognitive usability as well as technical structure.

Accessibility target

The target is WCAG 2.2 Level AA, not a self-certification.

The site is being designed and reviewed against WCAG 2.2 Level AA practices. Automated checks and code review can catch many issues, but they do not prove that every page works perfectly with every browser, device, zoom level, or assistive technology combination.

Accessibility review is therefore treated as an ongoing design and testing process rather than a one-time badge.

Important boundaries

What this page does not certify

  • External AI tools: Course Design Promptbook cannot guarantee the accessibility of a third-party AI platform where you paste a prompt.
  • Copied content: Content can lose structure when copied into another system, depending on that system's editor and paste behavior.
  • Generated or downloaded documents: A document created by an AI service may require its own accessibility check before it is distributed to students or colleagues.
  • Linked websites: External resources operate under their own accessibility practices.

When the prompts become course materials

Accessibility still belongs in the course-design decision.

The prompts can help faculty think about modality, cognitive load, and accessibility-conscious activity design, but AI output should not be assumed to be accessible simply because it was generated from an accessibility-aware prompt.

Before distributing new course materials, check the actual document, page, media, or activity in the system where students will use it. Follow your college's accessibility process and available support.

Accessibility feedback

Barriers are useful information.

If something on the site is difficult to navigate, read, operate, or understand, that is a design issue worth fixing. A direct project contact will be added with the full About page; until then, accessibility findings should be treated as part of the site's ongoing review rather than as proof that a user should simply work around the barrier.
